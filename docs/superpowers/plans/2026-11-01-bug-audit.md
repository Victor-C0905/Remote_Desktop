# Quirel 全项目 Bug 与逻辑漏洞排查计划

> **For agentic workers:** REQUIRED SUB-SKILL: 用 subagent-driven-development（推荐，按任务派发并行子代理）或 executing-plans 执行本计划。步骤用 checkbox（`- [ ]`）跟踪。

**目标：** 对 quirel 客户端（src-tauri + 前端）、quireld（agent）、quirel-protocol 三个组件做一轮系统性 bug / 逻辑漏洞排查，产出一份核实过的分级 finding 报告。

**架构：** 排查为**只读**任务——不改任何代码、不建分支、不提交。先跑基线（编译器/测试先暴露确定性错误），再按风险从高到低人工审查 6 个目标区，最后横切扫描 + 汇总验证。T1–T6 相互独立，可并行派发子代理；所有子代理 finding 必须经二次核实（回读被引用的代码行）才能进报告。

**技术栈：** Rust（3 组件，约 3.7 万行）+ TypeScript/React（约 3.2 万行），vitest + cargo test。

---

## 全局约束（AGENTS.md 红线）

- 只读排查：禁止修改源码、禁止创建/切换分支、禁止提交。产出仅为报告文件。
- 报告文件写入 `docs/audits/2026-11-01-bug-audit-report.md`（新建目录，不触碰源码）。
- 审查中触碰 §5.1（浏览器会话所有权）与 §6（窗口坏帧）相关文件时，必须先读
  `docs/window-flash-rules.md` 对照既有结论，避免把「设计如此」误报为 bug。

## Finding 严重度定义

| 级别 | 含义 | 示例 |
|---|---|---|
| P0 | 安全漏洞 | 未授权访问、路径穿越、命令注入、凭证泄露 |
| P1 | 崩溃/数据损坏/状态机破坏 | 死锁、会话丢失、协议错位、资源泄漏到失控 |
| P2 | 功能错误/边界条件 | 错误处理缺失、越界、竞态、i18n 缺键 |
| P3 | 代码异味/脆弱点 | unwrap 滥用、错误吞掉、魔数超时 |

## 每条 Finding 的产出格式

```markdown
### [ID] 标题 (P级别)
- 位置: path/to/file.rs:123-145
- 现象: 什么输入/时序会触发什么错误行为
- 证据: 被引用代码的关键行摘录（必须与源文件逐字一致）
- 建议: 修复方向（不写实现代码）
```

## Phase 1 — 高危区审查（T1–T6，独立可并行）

每个 track 的执行方式：通读指定文件 → 对照「关注点清单」逐条核对 → 产出 finding
草稿（含逐字代码摘录）。子代理只报告不修改。

### Task T1: 协议层正确性（quirel-protocol + agent/protocol）

**Files:** `quirel-protocol/src/{envelope,types,subscription,stats,lib}.rs`、
`quirel-protocol/tests/wire_compat.rs`、`agent/src/protocol/{raw_frame,transport_frame,serde,generated,mod}.rs`

- [ ] 关注点：
  - 帧解析：长度字段上限校验（防恶意超长帧/OOM）、半包/粘包处理、非法输入是否 `return Err` 而非 panic；
  - serde 兼容：枚举新增变体后旧对端反序列化行为（是否 `#[serde(other)]`/非穷尽 match）；
  - 双端对称：`generated.rs` 与 quirel-protocol 类型是否有手工镜像（漂移风险）；
  - subscription/stats 计数器溢出、订阅泄漏（订阅后不取消的场景）；
  - wire_compat 测试覆盖度：哪些消息类型没有被 round-trip 覆盖。
- [ ] 产出：finding 草稿列表。

### Task T2: agent 安全面（远程攻击面，最高优先级）

**Files:** `agent/src/auth/*`（challenge/executor/path_guard/namespace/rate_limiter/session/pam/ssh/stats/mod）、
`agent/src/worker/handlers/{file,command,session,system,shutdown,mod}.rs`、
`agent/src/{cert,transfer_limit,transfer_session,audit}.rs`、`agent/src/config.rs`

- [ ] 关注点：
  - 认证：challenge 是否恒定时间比较、nonce 重放、rate_limiter 绕过（按 IP 还是按会话、重置时机）、会话过期与并发登录；
  - path_guard/namespace：`..` 穿越、符号链接逃逸、绝对路径/UNC/空字节、大小写（跨平台）；
  - command.rs：命令拼接注入、shell 元字符、参数白名单完整性；
  - file.rs：下载/上传的路径校验一致性、临时文件权限与清理（对照 plans 里 transfer-error-polish 的既有结论）；
  - transfer_limit：限额绕过（分块计数 vs 字节计数、断点续传重置）；
  - audit：审计失败是否静默（审计被绕过而无日志）；
  - cert.rs：证书校验逻辑是否可被跳过。
- [ ] 产出：finding 草稿列表（P0 候选主要来自本 track）。

### Task T3: agent 生命周期与并发

**Files:** `agent/src/manager/*`（16 文件：session/session_connection/worker_manager/pty_registry/pty_output/orphan_reaper/crash_detector/signal_handler/ipc_server/hot_update_coordinator/connection/auth/protocol_adapter/mod）、
`agent/src/{event_bus,file_stream,diff,handler,lib,main}.rs`、`agent/src/worker/{session_manager,session_process,session_protocol,ipc_client,pty_factory,mod}.rs`、`agent/src/server/{quic,websocket,proxy,mod}.rs`

- [ ] 关注点：
  - 锁：多把 Mutex/RwLock 的获取顺序是否全局一致（画依赖图找死锁环）；
  - 状态机：manager↔worker↔session 三层生命周期，异常退出路径是否都走到清理（对照 crash_detector/orphan_reaper 的意图，找漏网的孤儿状态）；
  - 重连：QUIC/websocket 断线重连时旧会话状态是否残留、消息序号是否错位；
  - channel：send 到已关闭 channel、无界 channel 积压；
  - signal_handler/shutdown：优雅关停顺序、二次信号处理；
  - hot_update：热更新中途失败的状态回滚。
- [ ] 产出：finding 草稿列表。

### Task T4: 客户端 Rust 侧（src-tauri）

**Files:** `src-tauri/src/{connection,credentials,transfer,terminal,errors,ui_logging,main,lib}.rs`、
`src-tauri/src/proxy/{socks5,browser,browser_settings,browser_window,webview_host,suggest,mod}.rs`

- [ ] 前置：先读 `docs/window-flash-rules.md`（§6 红线背景）。
- [ ] 关注点：
  - credentials.rs：密钥存储方式、日志是否打印敏感值（对照 ui_logging 的脱敏意图）；
  - connection.rs：重连状态机、超时与取消（token 是否真的能取消进行中的 IO）；
  - transfer.rs：并发传输上限、断点续传一致性、磁盘写失败处理；
  - terminal.rs：PTY 输出缓冲无界增长、宽字符/转义序列边界截断；
  - socks5.rs：协议解析对恶意输入的健壮性（这是本地代理，暴露给本机浏览器）；
  - §6 红线核对（只核对是否被破坏，不改）：
    `lib.rs` 的 WM_ERASEBKGND 是否仍以 `WINDOW_BG_COLORREF` 填色、子窗口「不擦」链、
    `transparent(false)`、壁纸变更是否走 `set_window_background_color` 同步、
    `webview_host.rs`/`browser_window.rs` bounds 变更链路。
- [ ] 产出：finding 草稿列表。

### Task T5: 前端窗口系统与会话原子性（§5.1 红线）

**Files:** `src/window-system/*`（18 文件，重点 `core/{WindowManager,WindowRegistry,Window,WindowCollection}.ts`、
`init.ts`、`zOrder.ts`）、`src/apps/browser/*`（init/registry/heartbeat 相关）、
`src/window-system/core/WindowManager.session.test.ts`（先读，理解既有契约）

- [ ] 关注点（对照 AGENTS.md §5.1）：
  - 红线 1：React 组件的 effect/cleanup 中是否有 `browser_close_window` / `proxy_stop_session` 调用
    （grep 全前端 + 逐处人工确认调用路径）；
  - 红线 2：可见性——心跳 >3s 隐藏、恢复后按命令态 re-assert 的实现是否存在绕过路径
    （一次性前端指令改可见性而未落命令态的地方）；
  - 红线 3：grep 所有 portal 浮层是否带 `data-browser-overlay`（列出缺失清单）；
  - WindowManager/Registry 本身：事件监听器泄漏、窗口 id 复用冲突、zOrder 稳定性、
    异步竞态（连续开关同一窗口）；
  - browser_refresh_tabs 全量回灌：刷新后 tab 状态与后端真实状态是否可能漂移。
- [ ] 产出：finding 草稿列表。

### Task T6: 前端业务逻辑

**Files:** `src/stores/*`、`src/hooks/*`、`src/context/{ServerManager,WallpaperContext}.tsx`、
`src/shell/*`、`src/apps/*`（browser/terminal/TextEditor/各 viewer 的核心逻辑文件）、
`src/file-formats/*`

- [ ] 关注点：
  - zustand store：跨 store 订阅导致的更新风暴/陈旧闭包、persist 版本迁移（serversStore 凭证字段）；
  - WallpaperContext：变更是否触发 Rust 侧 `set_window_background_color`（§6 联动）；
  - useTransferProgress/useSubscription：事件监听器卸载清理、进度乱序/丢失；
  - TextEditor diff 与归档解析器：大文件、空文件、二进制伪装文本的边界；
  - fileGuard/openRemoteFile：前端路径校验与后端 path_guard 是否双重防线（前端口绕过是否可达后端）；
  - i18n：`t()` 缺键静默回退、插值注入；
  - 各 viewer：解析恶意/损坏文件的异常边界（是否崩整个 React 树，RootErrorBoundary 覆盖面）。
- [ ] 产出：finding 草稿列表。
