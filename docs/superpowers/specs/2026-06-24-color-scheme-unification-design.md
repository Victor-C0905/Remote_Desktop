# 颜色方案统一管理设计文档

> 版本: v1.0 | 日期: 2026-06-24
>
> 目标：统一管理整个项目的颜色方案，引入暖色调色板，替代原有的冷灰色系，建立系统化的颜色管理规范。

---

## 一、设计背景

### 1.1 当前问题

- 颜色定义分散：部分使用 CSS 变量，部分硬编码
- 冷灰色系：当前使用冷色调灰色（#f0f0f0, #ebebeb, #d5d5d5），缺乏温度感
- 缺乏统一规范：不同组件使用不同的颜色值，难以维护
- 扩展性差：后续项目无法复用统一的颜色方案

### 1.2 设计目标

- **统一管理**：所有颜色通过 CSS 变量集中管理
- **暖色调**：引入 RGB(250,250,250) 和 RGB(245,240,230) 作为新的基调色
- **系统化**：建立清晰的颜色层次和使用规范
- **可复用**：为后续项目提供统一的颜色方案模板

### 5.2 替换规则

**CSS 文件替换规则：**

```css
/* 旧代码 */
background: #ffffff;
border-color: #d5d5d5;

/* 新代码 */
background: var(--view-bg);
border-color: var(--sidebar-border);
```

**TSX 文件替换规则：**

```tsx
// 旧代码
style={{ background: '#f0f0f0' }}

// 新代码
style={{ background: 'var(--card-bg)' }}
```

**特殊情况处理：**

- **功能性颜色**（状态指示、图表）保持不变
- **第三方组件**（xterm.js）保持原有配色
- **透明度颜色**（rgba）根据用途决定是否替换

## 六、颜色使用规范

### 6.1 使用原则

1. **优先使用 CSS 变量** - 所有颜色必须通过 CSS 变量引用
2. **禁止硬编码** - 除非是功能性颜色（状态、图表）
3. **遵循层次** - 按照背景 → 卡片 → 边框的层次使用
4. **保持语义** - 变量名反映用途（如 `--card-bg` 用于卡片背景）

### 6.2 常见用途映射

| UI 元素 | 应使用的变量 |
|---------|-------------|
| 窗口主背景 | `var(--window-bg)` |
| 内容区背景 | `var(--view-bg)` |
| 卡片背景 | `var(--card-bg)` |
| 卡片悬停 | `var(--card-hover)` |
| HeaderBar | `var(--headerbar-bg)` |
| 侧边栏 | `var(--sidebar-bg)` |
| 边框 | `var(--border-color)` 或 `var(--sidebar-border)` |
| 主文字 | `var(--text-primary)` |
| 次文字 | `var(--text-secondary)` |
| 禁用文字 | `var(--text-disabled)` |
| 强调按钮 | `var(--accent-bg)` |

### 6.3 新增颜色变量规范

如果需要新增颜色变量，遵循以下命名规范：

```css
/* 格式：--[元素]-[属性] */
--button-bg:       /* 按钮背景 */
--button-hover:    /* 按钮悬停 */
--input-bg:        /* 输入框背景 */
--input-focus:     /* 输入框聚焦 */
--tooltip-bg:      /* 提示框背景 */
```

## 八、后续项目复用方案

### 8.1 颜色方案模板

为后续项目提供可复用的颜色方案：

```css
/* 复制以下内容到新项目的 styles/adwaita.css */

:root {
  /* ── Warm Gray Palette (暖灰色调) ── */
  --window-bg:      #fafafa;
  --view-bg:        #f5f0e6;
  --card-bg:        #f5f0e6;
  --card-hover:     #ebe5d9;
  --headerbar-bg:   #ebe5d9;
  --sidebar-bg:     #ebe5d9;
  --sidebar-border: #d5d0c4;

  /* ── Accent Colors (GNOME Blue) ── */
  --accent-bg:      #3584e4;
  --accent-fg:      #ffffff;
  --accent-hover:   #1f75d1;
  --accent-active:  #1a5fb4;

  /* ── Text Colors ── */
  --text-primary:     rgba(0, 0, 0, 0.87);
  --text-secondary:   rgba(0, 0, 0, 0.60);
  --text-disabled:    rgba(0, 0, 0, 0.38);
  --text-on-accent:   #ffffff;

  /* ── Borders ── */
  --border-color:   rgba(0, 0, 0, 0.15);
  --border-focus:   #3584e4;
}
```

### 8.2 使用指南

后续项目应遵循：

1. **直接复用** `adwaita.css` 文件
2. **禁止硬编码**颜色值
3. **遵循颜色使用规范**（见第六节）
4. **保持一致性** - 所有项目使用相同的暖色调

## 九、风险评估

### 9.1 潜在风险

| 风险 | 影响 | 缓解措施 |

| 第三方组件冲突 | 显示异常 | 保持第三方组件原有配色 |

### 9.2 回退方案

如果新颜色方案出现问题：

- 保留原有 `adwaita.css` 的备份
- 可快速回退到原有冷灰色系
- 分阶段实施，降低风险

## 附录：颜色对比示例

### A.1 旧颜色 vs 新颜色

```
旧冷灰色系：
├─ #ffffff (纯白) ──→ #fafafa (柔和白)
├─ #f0f0f0 (冷灰) ──→ #f5f0e6 (暖灰)
├─ #ebebeb (冷灰) ──→ #ebe5d9 (暖灰)
└─ #d5d5d5 (冷灰) ──→ #d5d0c4 (暖灰)

视觉效果：
冷灰色系：偏蓝调，感觉冷峻、科技感
暖灰色系：偏米色调，感觉温暖、舒适
```

| 颜色 | RGB 值 | 色调倾向 |
|------|--------|----------|
| `#fafafa` | (250, 250, 250) | 纯白，略微柔和 |
| `#f5f0e6` | (245, 240, 230) | 暖灰，米色倾向 |
| `#ebe5d9` | (235, 229, 217) | 中暖灰，象牙色 |
| `#d5d0c4` | (213, 208, 196) | 深暖灰，沙色 |
