# Quirel 多语言（i18n）功能设计

日期：2026-10-13
状态：已批准（设计评审通过）

## 1. 背景与目标

Quirel 当前所有用户可见文案为硬编码中文，无任何 i18n 基础设施。本设计为应用增加可设置的语言功能：

- 用户可在设置中切换界面语言（首期：简体中文、English），切换即时生效、持久化、重启后保持；
- **语言包可增量扩展**：新增一种语言 = 新增一个 TS 词典文件 + 注册表加一行，无其他改动；
- Rust 后端错误消息彻底错误码化，任何语言下错误提示完整、功能不因语言切换而损坏。

### 需求决策记录

| 决策点 | 结论 |
|---|---|
| 语言包形式 | 仓库内 TS 文件，随版本发布（非运行时外部加载） |
| 首期语言 | 简体中文（zh-CN）+ English（en-US） |
| Rust 错误消息 | 彻底错误码化（非前端兜底映射） |
| 技术选型 | react-i18next（i18next + react-i18next） |

### 现状关键数据（2026-10-13 分析）

- 前端 TS/TSX 约 23,500 行，含中文行 4,488（约 55% 为注释，不需处理）；运行时 UI 文案约 400~500 处。
- Rust 约 7,000 行，约 136 处中文 `Err(String)` 通过 Tauri invoke reject 直达用户界面。
- 31 处系统 `alert()/confirm()`；10~14 个测试文件断言中文文案。
- 已有两处**中文子串逻辑判断**（功能隐患，英文环境静默失效）：
  - `src/types/errors.ts:132`：`msg.includes("未找到连接")`
  - `src/apps/FileManager.tsx:339`：`errMsg.includes('权限不足')`
- 设置系统：`src/stores/settingsStore.ts`（zustand + persist，存储后端 `@tauri-apps/plugin-store` 的 `settings.bin`，persist key `"quirel-settings"`）。主题切换的三条生效路径（`onRehydrateStorage` 预设 → `useTheme` 的 `useLayoutEffect` → 全局应用函数）是本设计的复用模板。

## 2. 总体架构

新增 `src/i18n/` 模块：

```
src/i18n/
  index.ts          # i18next 初始化 + RESOURCES 语言注册表
  types.ts          # TranslationSchema 类型定义
  locales/
    zh-CN.ts        # 中文词典（source of truth，约 500 key）
    en-US.ts        # 英文词典
```

### 2.1 词典与类型约束（语言包增量协议的核心）

- `zh-CN.ts` 导出嵌套对象（按功能域分组，见 §3），是所有语言的 source of truth。
- `types.ts` 从 zh-CN 推导出**同形状、值为 string** 的类型：

```ts
import zhCN from './locales/zh-CN';

type Stringify<T> = { [K in keyof T]: T[K] extends string ? string : Stringify<T[K]> };
export type TranslationSchema = Stringify<typeof zhCN>;
```

- 其他语言词典标注 `TranslationSchema` 类型：**缺 key、多 key、嵌套结构与中文不一致均编译报错**。翻译不完整的语言包无法通过构建，不可能带伤上线。
- `index.ts` 维护语言注册表：

```ts
export const RESOURCES = {
  'zh-CN': { label: '简体中文', resource: zhCN },
  'en-US': { label: 'English', resource: enUS },
} as const;
export type Locale = keyof typeof RESOURCES;
```

### 2.2 新增语言包的操作协议

1. 在 `src/i18n/locales/` 新建 `<locale>.ts`，导出标注 `TranslationSchema` 的完整词典；
2. `index.ts` 的 `RESOURCES` 注册表加一行；
3. 完成。Settings 语言下拉框从 `RESOURCES` 渲染，新语言自动出现。

维护一份《新增语言包指南》（`docs/i18n-adding-a-language.md`）作为第四期交付物。

## 3. key 组织与词典结构

- key 按功能域一级分组，camelCase 命名：`common`、`appShell`、`settings`、`connection`、`fileManager`、`terminal`、`transfer`、`textEditor`、`systemMonitor`、`browser`、`archiveViewer`、`hexViewer`、`imageViewer`、`pdfViewer`、`themes`、`errors`、`about`。
- 每语言一个单文件（预计 500~700 行），不做多文件/namespace 拆分——便于翻译对照，符合"一个语言包 = 一个文件"的心智模型。
- 插值使用 i18next 语法：`"duration": "{{m}}分{{s}}秒"` → `t('transfer.duration', { m, s })`。
- fallback：`fallbackLng: 'zh-CN'`。任何语言缺 key 时显示中文兜底，绝不显示裸 key。

## 4. 语言状态与持久化

- `settingsStore` 新增字段 `locale: Locale`（默认 `'zh-CN'`）与 action `setLocale`。默认值与当前应用语言一致，老用户升级零感知。
- 持久化复用现有 persist 机制（`"quirel-settings"`），零额外存储工作。
- 生效路径（复用主题模式）：
  1. **启动**：`settingsStore` 的 `onRehydrateStorage` 回调中同步 `i18n.changeLanguage(locale)`，在 React 首次渲染前生效，防止语言闪烁；
  2. **切换**：新增 `useLocale` hook（参照 `src/hooks/useTheme.ts`），`useLayoutEffect` 响应 locale 变化调用 `i18n.changeLanguage()`；
  3. **全局**：同步更新 `document.documentElement.lang`。
- 切换语言即时生效，无需重启。
- 不做"跟随系统语言"（YAGNI，记入未来增强：设置项增加 `system` 选项，解析 `navigator.language`，`zh* → zh-CN`，否则 en-US）。

## 5. 组件接入规范

| 场景 | 用法 |
|---|---|
| React 组件 | `useTranslation()` 的 `t('domain.key')` |
| 非 React 纯 TS 模块 | 直接 import i18n 实例（项目无路径别名，用相对路径，如 `import i18n from '../../i18n'`）后调 `i18n.t('domain.key')` |

非 React 模块清单（改造点）：`src/hooks/useTransferProgress.ts`（系统通知文案）、`src/apps/openRemoteFile.ts`、`src/components/TransferStatusBar/transferGrouping.ts`、`src/stores/serversStore.ts`、`src/components/Dialog/ConfirmDialog.tsx`（内置默认按钮文案"确定/取消"改为 `t('common.confirm')`/`t('common.cancel')`）。

文案迁移范围：

- **迁入词典**：所有 JSX 文案、`title`/`placeholder`/`aria-label` 属性、`terminal.write()` 的演示文案、系统通知标题与正文、主题 `name`/`description`（themes.ts，`themes.paper.name` 等约 10 条）、`ERROR_MAP` 全部 title/message/action、时间/数量单位词。
- **不动**：代码注释、JSDoc、控制台日志（console/log 宏）、测试文件内部注释。这部分占全部中文的 55% 以上，明确排除以控制工程量。

## 6. Rust 错误码化

### Rust 侧

- 新建 `src-tauri/src/errors.rs`：
  - 错误码常量（snake_case 字符串，如 `frame_length_invalid`、`connection_not_found`、`permission_denied`）；
  - `AppError { code: String, params: HashMap<String, String> }`，Serialize 为 `{ "code": "...", "params": {...} }`；
  - 保留 `detail` 字段携带原始上下文（英文技术描述），仅用于日志排查，前端不直接展示 detail 正文（未知错误码兜底时可展示）。
- 迁移 `transfer.rs`（60+ 处）、`connection.rs`（76+ 处）的用户可见 `Err(String)` → `Err(AppError)`；`proxy/`、`terminal.rs`、`lib.rs` 中同类错误一并迁移。
- 控制台日志（`log!/warn!/error!` 的消息）保持原样，不翻译。

### 前端侧

- `src/types/errors.ts` 改造：
  - `ERROR_MAP` 从"错误码 → 固定中文"改为"错误码 → 词典 key"，渲染时 `t(key, params)`；
  - `parseConnectError` 支持解析 `{ code, params }` 结构；裸字符串（老格式/未知来源）兜底：尝试既有映射，否则原样展示。
- **修复中文子串判断缺陷**（本设计顺带交付的功能修复）：
  - `errors.ts:132` `describeTerminalFailure`：改为按错误码判断；
  - `FileManager.tsx:339` `errMsg.includes('权限不足')`：改为按错误码判断。

## 8. 测试策略

- vitest setup 统一初始化 i18n 为 `zh-CN`：现有中文断言（Terminal、TaskCard、ConnectionState、TextEditor 等 10~14 个文件）基本保持不动，最小化测试改动。
- 新增测试：
  - i18n 初始化与 fallback 行为；
  - locale 持久化/恢复（settingsStore 集成）；
  - `RESOURCES` 完整性运行时校验（类型约束之外的兜底）；
  - 错误码解析与 `ERROR_MAP` 词典化后的行为（`errors.test.ts`、`openRemoteFile.test.ts` 等需同步更新）。
- 中文子串判断修复后，相应行为测试按错误码改写。
