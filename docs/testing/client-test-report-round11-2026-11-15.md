## 二、发现与修复

### R11-02（P2）服务器添加/编辑对话框必填校验静默失败 —— 已修复

- **现象**：清空「服务器名称」或「主机地址」后点「保存」——对话框保持打开、无任何错误提示、按钮不置灰。用户不知道为什么存不上。
- **根因**：`AddServerModal.handleSubmit`（Settings.tsx:81）与 `EditServerModal.handleSubmit`（:329）以 `if (name && host)` 包裹整个提交块——空值时静默跳过。formError 内联错误机制已存在（私钥/keyring 错误在用），唯独必填场景没接。
- **修复**：两个 Modal 提交入口显式校验 `!name.trim() || !host.trim()` → `setFormError(t("settings.errors.requiredFields"))`（i18n zh/en 新增键）；提交值 trim（消除首尾空白入库）。
- **测试**：`server-modal-validation.test.tsx` 3 条（空值报错不提交 / trim 后提交 / Edit 变体），红→绿入库。

### R11-01（P3）服务器行编辑/删除图标按钮无 aria-label —— 已修复

- 纯图标按钮仅 `title`（悬停提示），无 `aria-label`——屏幕阅读器不可达；同窗窗口控制按钮（最小化/最大化/关闭）均双齐全。已补 `aria-label={t("settings.editTip"/"deleteTip")}`。

### 观察项（不改码）

- **O1（P3）**：通知面板「全部已读」按钮与「开面板即标已读」行为重复——打开面板后按钮恒为无操作。视觉冗余，建议后续移除或改为「清除全部」（现「清除」按钮已存在，两键语义高度重叠）。
- **O2（P3）**：通知中心累积 80 条（含 11月12日 测试期错误），无时效衰减/上限——长期使用会膨胀。属产品设计取舍，记录待用户拍板。
- **O3（P3）**：端口输入 `onChange={parseInt||8443}`——键入 0/清空会被静默替换为 8443，且无 1-65535 保存钳制。低频场景，记录待办。

## 二B、信息架构整改：文字墙 → InfoTip（用户反馈驱动）

用户指出界面大量散落的说明文字是不合理设计（"文字说明堆满 UI，不如做命令行"）——
R11 第一轮探针盯行为缺陷，漏掉了信息架构层面的文字墙问题。复查九节截图确认
重灾区后当轮整改（`01a280f`）：

- **新增 InfoTip 组件**（ⓘ 图标 + 原生多行 title，键盘可达，零依赖），信息架构
  规范写入组件注释：一行能说清的短提示内联；背景知识/安全注意/多行解释收进
  InfoTip，界面不铺说明段落。
- **浏览器节**（重灾区，一张卡片两坨文字墙）：SOCKS5 端口三行说明 → 标签旁 ⓘ；
  卡片底部四行段落删除 → 「内置浏览器」标题旁 ⓘ。
- **添加/编辑服务器对话框**：私钥三行提示 → 「私钥文件」标签旁 ⓘ（补入
  「留空 = 保留已保存凭据」的编辑语义说明，此前只存在于代码注释）。
- **i18n**：privateKeyHint1/2/3、socks5PortHint、browserHint → privateKeyTip /
  socks5PortTip / browserTip（zh/en），文案按「结论先行、逐行一个事实」重写。
- **实机验证**：浏览器节 textWalls=0 / hintBlocks=0 / infoTips=2；对话框公钥认证
  下 ⓘ title 正确；节内版面从「3 个设置项 + 半版说明文字」恢复为纯设置项。
  前后截图 `r11s-sec5.png` vs `r11s-sec5-after.png`。
- 保留的单行提示（均为有用功能教学，不属文字墙）：终端节 shell 入口、传输
  设置「仅对当前连接的服务器生效」、FM 搜索/地址栏 placeholder。

## 二D、SP-3 结案：webview 视口「冻结」为测试事故，非应用缺陷

用户指示优先解决 SP-3（webview 视口不随 OS 窗口缩放）。按红线流程只调查
未改码（`quirel-redlines-window` 技能 + `window-flash-rules.md` 已读；窗口
代码零改动，无需 dupcap 回归）。

- **决定性实验**（干净重启实例）：挂前端 resize 监听 → MoveWindow 1200x900
  → **事件正常触发、innerWidth 跟随更新（1186）**；缩到 900x620 → media980
  命中、TopBar metrics 按新策略隐藏 ✓；窄窗下 FM 深层路径面包屑收拢
  `[🏠 … deep-leaf]` 生效、当前段在栏内 ✓——#1/#3/#4 的修复在**真实窗口
  缩放**下全部成立。
- **根因还原**：此前观察到的视口冻结（1024/786 卡死）是**测试事故**——一次
  参数解析错误的 sendinput drag（959,340 → 0,0）抓住了 Quirel 窗口右缘把
  窗口拖向近零宽，WebView2 布局态损坏（视口卡 786 等怪值）后进程延迟退出。
  中毒实例上的测量全部失真。
- **附带事件**：死亡实例的进程退出原因未查明（与滥用拖拽强相关；R8-N3 亦
  记录过三件套自然退场）。如正常使用中再次出现无故退出，单独立项排查
  （挂 stdcrash dump / WER）。
- **测试规范追加**：OS 级窗口操作前必须确认目标窗口在前台（osburst 首帧
  核对），否则键鼠注入会打到覆盖在上的其它应用（本次 ZCode 被误拖）。
