## 三、发现

### R12-02（P2）原生文件对话框整体失效（save + open 双路径实证），流程静默挂起 —— 待人工复核

- **现象（升级定性）**：两处独立入口均复现——
  1. FM「下载」→ `handleDownload` 执行（日志实证 `[FileManager] 下载文件: …`）→ `save()` → 对话框不出现，流程在 `await save()` 静默挂起，传输恒「无传输」；
  2. 设置→外观→「导入本地壁纸」→ `open()` → 同样无对话框。
  UIA 枚举（pid 全窗 + #32770 对话框类）均只有主窗——对话框**从未创建**，非「弹出后被遮挡」。
- **已排除**：capabilities 权限（`dialog:allow-save/open` 在列；同列表的 opener 权限实际工作——msedge 打开成功证明 main 窗口 IPC 权限链路通）；版本错配（Cargo `tauri-plugin-dialog` 2.8.3 与 npm `@tauri-apps/plugin-dialog` 2.8.3 同步）。
- **疑点收敛**：plugin-dialog 在本 dev 构建（tauri dev）中的运行时失效——需 `RUST_LOG=debug tauri dev` 重启后重现调用，观察 `tauri_plugin_dialog` target 的 IPC 日志定位（本轮测试任务未再深入，改码/改版本超出测试范围）。
- **复现**：环境已保留（客户端 + quireld r12 运行中；`/root/.bash_history` 与壁纸按钮两处入口）。
- **影响**：下载与本地壁纸导入功能不可用（P2——用户有明确感知：点击后什么都没发生）。历史轮次未覆盖此路径（本轮首次实测对话框类交互）。

### R12-01 撤回记录

终端「输入乱序回显」（`-----KOLANIMRETR'o'h'ce`）初判为应用缺陷，经三路判别
（慢速注入顺序正确 / CDP `Input.dispatchKeyEvent` 全部正常 / 仅 WScript SendKeys
异常）确认为**测试注入工具局限**——WScript SendKeys 的 VK 路径（Enter/Space/组合键）
在 WebView2 下不可靠、高速字符注入存在时序伪影。撤回，非应用缺陷。

## 四、测试注记（工艺沉淀）

1. **终端输入自动化统一走 CDP `Input.dispatchKeyEvent`**（本轮新增 `r12-cdp.mjs type`
   命令）：OS 层 SendKeys 在 WebView2 不可靠；CDP 注入与真实键盘事件同层级，xterm 完整接收。
   注意：`code` 字段须合法（`Key-` 形态会被忽略导致字符丢失——`-` 等符号键用 text 通道直发）。
2. **原生对话框自动化配方**：UIA 对 tauri 原生 MessageBox 的按钮枚举不稳定；
   可靠路径 = `WScript.Shell.AppActivate(标题)` → 加速键（`y` 对应「是(Y)」）。
3. **前台纪律再次生效**：B9 注入前前台核对发现被占即中止（R11 教训的正确执行）。
4. 合成右键菜单事件必须携带真实 `clientX/clientY`（默认 0,0 会命中空白菜单语义）；
   但注意 R11 二I 语义下「未选中行右键=刷新菜单」本身是正确行为，不要误报。
