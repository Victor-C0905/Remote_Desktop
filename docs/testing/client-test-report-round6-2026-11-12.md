## 二、缺陷详录

### R6-P2-01 点击失效常用条目静默清空列表

**复现**（100%）：侧边栏常用组点击 `/root/gone-dir-xyz`（服务器上不存在）→ 无错误提示，
路径条回退显示上一目录（🏠root），但列表 **0 行**、状态栏「0 个文件夹, 0 个文件」；
重新点击「主目录」→ 25 行正常加载。

**影响**：用户看到空列表会误以为文件丢失；且失效条目永远留在常用组。
**根因方向**：loadDir 失败后未恢复上一目录的 entries（清了列表没回读），失败也无 UI 反馈；
失效条目无清理机制。**建议**：失败时回读上一目录 + 通知中心提示 + 连续失败 N 次后从常用组剔除。

### R6-P2-02 服务器无标准位置时回退布局产生幽灵条目

**事实链**：agent `collect_common_locations` 正确过滤不存在的目录（/root 无 XDG 目录 → 返回 0）→
客户端 `commonLocations=[]` → `buildSidebarSections` 按「旧版 Agent 兼容」回退硬编码布局 →
文档/下载/图片/音乐/视频 指向不存在的路径 → 点击全部静默失败（R6-P2-01 路径）。

**根因（设计层）**：**新版 Agent「合法返回 0」与「旧版 Agent 无字段」在客户端不可区分**
（`user.common_locations ?? []` 把两者都归为空）→ 兼容回退误伤真实空态。
**修复方向（需拍板）**：a) 协议层区分（CurrentUserResponse 用 Option 标记字段存在性）；
b) 回退布局收窄为仅主目录；c) 点击前探测/失败提示兜底。a+b 组合最干净。

### 补充发现：S-03 清除数据会连带清除系统凭据

第五轮 S-03（清除所有本地数据）后重新发现：Windows 凭据管理器中该服务器的密码被一并清除，
仅还原 .bin 文件**无法恢复**连接能力（本轮靠重置 WSL 密码 + 在客户端重录凭据恢复）。
属「清除所有本地数据」预期语义内（凭据确实属于本地数据），但**备份/还原流程需知晓**：
可迁移的只有 .bin，凭据必须重录。

### 测试基建备注：E2E-05 假阳性

`e2e/specs/smoke.e2e.ts` 的 E2E-05（常用分组）在 dev 基线上是**假阳性通过**：dev 侧边栏
「主目录」项的 title="/root" 恰好匹配了检测条件。待修：常用检测需锚定「常用」分区容器，
而非任意带 title 的侧边栏项。
