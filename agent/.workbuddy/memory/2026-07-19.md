# 2026-07-19 工作日志

## quireld 构建体积分析

对项目 target 目录膨胀至 2.0GB 的根因分析，识别出 6 项不合理设计：

1. **rustls 双加密后端**（最严重）：`Cargo.toml` 中 `rustls = { features = ["ring"] }` 未设 `default-features = false`，导致 ring + aws-lc-rs 同时编译，aws-lc-sys 还需 cmake 构建 C 库，浪费 ~260MB。代码实际只用 ring（main.rs:31）。
2. **版本分裂**：getrandom 3 版本、windows-sys 3 版本、rand/thiserror 各 2 版本，proc-macro2 15 份实例。
3. **tokio "full" 过宽**：libtokio.rlib 达 43MB，实际只需 rt/macros/net/io-util/sync。
4. **sysinfo 拉入 windows crate**：121MB 的 libwindows.rlib，项目目标平台是 Linux 却在 Windows 编译。
5. **平台条件依赖未隔离**：nix/libc 是 Unix-only 但放在全局 dependencies。
6. **incremental 缓存堆积** 228MB。

修复方案已给出：禁用 rustls 默认特性、tokio 精确特性、sysinfo 禁用默认特性、Unix 依赖移到 `target.'cfg(unix)'` 块。预期 target 从 2.0GB 降至 ~800MB。

Release 二进制本身仅 5.32MB，体积合理。

## 深入分析：50MB 目标可行性

对二进制进行 ELF 段级分析：
- .text 76.1%（4.24MB 机器码）、.rodata 8.5%、.eh_frame 6.0%、.gcc_except_table 2.6%
- 二进制中 aws-lc 标记为 0（LTO 死代码消除已生效），证明 aws-lc-rs 仅浪费构建产物，不影响最终二进制
- 动态链接：仅依赖 libc.so.6、libgcc_s.so.1、libm.so.6

50MB 目标判定：
- **二进制**：5.32MB → 优化后 3.8MB（panic=abort 省 480KB + opt-level=z 省 200KB + quinn 禁用 platform-verifier 省 100KB），UPX 压缩后 1.5MB。已达标。
- **分发包**（二进制+cert+key+toml）：~4MB。已达标。
- **target/ 构建目录**：即使全优化 + cargo clean + 仅 release 构建，最低 ~180MB。受限于 Rust 编译模型（200 crate × 0.6MB/crate = 120MB .rlib 下限）。不可行。

最终报告已输出至 SIZE_ANALYSIS_REPORT.md，包含完整优化版 Cargo.toml。

## 发布优化方案文档

生成 OPTIMIZATION_PLAN.md，将优化分为三级：
- P0（必须做）：移除 aws-lc-rs 双后端 — 1 行改动，消除 cmake 依赖，编译快 2-3 分钟
- P1（建议做）：tokio 精确特性、quinn 禁用 platform-verifier、notify 禁用 macOS 特性
- P2（锦上添花）：sysinfo 禁默认特性、Unix 依赖移到平台条件块、tempfile 移到 dev-deps
- 不建议做：panic=abort、opt-level=z、UPX 压缩

文档含完整可替换的 Cargo.toml 和部署方式说明。
